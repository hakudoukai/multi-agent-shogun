## §5 形の選択(貴殿が選び理由を述べよの下命に従う)— ★warn一択、block不採用★

**選択: warn(常に非block・exit 0固定・stderrへ即応可能な回避手順を同梱)**

**block不採用の理由(実測に基づく)**:
1. §1の通り、門は「正当」と「不当」を構文的に区別できない。区別できぬ道具でblockすれば、
   §2で確認した★repo内の安全な13箇所以上と同型の用法★を持つ将官が、いつか同じ形をad-hocで
   打った瞬間に手を止められる。これは**DD-169 guardが本日実際に当職の報告文を塞いだ実害**
   (下命文に明記)と同型の再演になる。
2. karo-second便自身が「how を知らぬ者が how を指定するな(委員長殿)」「選ぶは貴殿」と
   委ねている以上、当職はここでの選択理由を明記する義務を負う——block化は「正当用法を
   一律停止する」という重い代償を、実証された便益(推論の誤りそのものを構文的に防げるわけではない)
   に見合わぬ形で払う。

**warn単独でも不十分な点(条③の要求を満たす形へ補強)**:
単純warnは「読まれねば効かぬ」(karo-second便②の欠点として自ら指摘済)。∴ 出力に
**同じ場所へ回避手順を同梱**する(受入条件⑶):

```

 判定に使う前に確かめよ:
  ① grep -c は 0件でも exit=1 になる。生の印字文字列(空文字列を含む非空)を
    直接 truthy 判定に使わず、値を変数へ捕捉し数値比較(-gt/-eq)で判定せよ
  ② pgrep -fc は bash -c 等の呼出殻まで数える。列挙(pgrep -f本体+ps -o comm,args)
    で実体を確かめよ
  ③ git check-ignore -v は白名簿(!パターン)一致も同じ書式・exit=0で出す。
    -v を外した素の exit code のみを見るか、git status --short の ??/!! を見よ
 参照: memory tool-output-is-not-tool-verdict / gitignore-whitelist-silent-drop /
       watcher-count-lies-enumerate-instead / docs/incident_logs/2026-08-04_w176_misread_tool_ledger_a4.md
```

これはblockでもなく単純warnでもない、下命文が示す「中間」に近い——ただし将軍second案の
「拒むが理由と回避法を同じ出力に出す」の**拒む部分のみ採らず**、非block(exit 0)で
理由と回避法だけを常時同梱する形とした。理由=§5冒頭の実測(block化の代償が便益に見合わぬ)。
