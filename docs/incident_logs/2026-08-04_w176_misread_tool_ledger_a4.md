## §1 主表 — 二人以上が同じ誤読をした道具(3道具・4事例、①は入口違いの二事例を含む)

### ① `git check-ignore -v <path>`

- **誤読者**: karo-second・将軍second(各自別々に実施、queue/inbox/karo-second.yaml #594-600 / #(将軍second→家老の便で確認))
- **誤読を招く「形」**(人の不注意ではなく形を書く):
  `-v` 付きで実行すると、**除外(ignore)パターンにも、除外の否定(`!`で始まる白名簿パターン)にも同じ書式で
  マッチ行を出力し、かつ exit code も両者とも 0 になる**。当職が実測で確認した内容(単なる伝聞の再掲ではない):
  ```
  # 真に除外されるfile
  $ git check-ignore -v queue/some_ignored_file.txt
  .gitignore:7:*    queue/some_ignored_file.txt
  $ echo $?
  0

  # 白名簿(!)で除外解除されているfile(実際は追跡対象)
  $ git check-ignore -v docs/incident_logs/2026-08-04_w176_....md
  .gitignore:202:!docs/incident_logs/*.md    docs/incident_logs/2026-08-04_w176_....md
  $ echo $?
  0   ← 除外されていないのに 0(「一致した」の意味であって「除外された」の意味ではない)
  ```
  **★当職の追加実測(karo-second/将軍second の記述より一段深い所まで確認)★**: 実は `-v` を外した素の
  `git check-ignore <path>` なら、この同じ白名簿fileに対して **exit=1(除外されていない、が正しく返る)**。
  つまり誤読の真因は「exit codeでしか可否が分からぬ」のではなく、**`-v` フラグ自体が exit code の意味を
  変える**(素の呼び出しは正しい・`-v`を足すと途端に紛らわしくなる)。二人の記述(「可否はexit codeにのみ在る」)は
  部分的に不正確であり、この点は本台帳が唯一補正した箇所として明記する。
- **正しい確かめ方**: `git status --short <path>` を見て `?? <path>` として現れるか(追跡対象外かつ除外されていない=
  白名簿で復活)を確認する。または `-v` を付けずに `git check-ignore <path>` を実行し、その exit code のみを見る
  (`-v`のマッチ行を見ない)。

### ①-b `git check-ignore`(同じ道具の二つ目の誤読・出力の読み違えではなく標本の取り方)
