## 3. ★契約 C-1 の字面と実態の突合 (将軍裁の課題)★

### 契約の字面 (a2 票 §5 逐語)

> **C-1 掃除判定は `codex_residue_cleanup()` ★一つ★ に閉じる。** テストは本関数を直に呼ぶ事。

### 最終断面の実態

判定の材料は **`composer_line_normalized()` へ括り出されて居る**。
`codex_residue_cleanup()` は其れを呼び、大域 `COMPOSER_CONTENT` / `COMPOSER_LINENO` / `COMPOSER_CAP` を受け取って判ずる:

```
codex_residue_cleanup 内
  ├ composer_line_normalized "$pane"      ← 正規化 (C-4 ⑴〜⑸) は此方に在る
  ├ content="$COMPOSER_CONTENT"           ← 大域経由で受け取る
  └ COMPOSER_CAP | sed "${COMPOSER_LINENO}d" | grep -qF   ← 着弾確認
```

∴ **「一つに閉じる」は字面としては 已に成り立たぬ**。判定は **二関数に跨って居る**。

### ★然れど当職の10形は一形も書換えずに通過した★ (将軍裁 併記事項)

**字面は破れたが、契約が守ろうとした物は破れておらぬ**に御座る。理由:

- C-1 の実質は **「テストが本関数を直に呼べる事」** ―― 之は不変。
- C-2 (prefix=第1引数 / pane=第2引数) 不変。
- C-3 (RC + `CODEX_RESIDUE_STATE`) 不変。
- ∴ **試験の面 (interface) は一字も動いておらぬ**。動いたのは **内部の割り方** のみ。

### 字面合わせの要否 ―― **当職の見立ては「要・但し軽微」**

| 条 | 現字面 | 実態 | 具申 |
|---|---|---|---|
| C-1 | 「判定は `codex_residue_cleanup()` **一つに閉じる**」 | 二関数に跨る | 「**掃除の判定は `codex_residue_cleanup()` を ★入口★ とし、テストは本関数を直に呼ぶ。内部の分割は問わぬ**」へ改めるが良しと存ずる。**護るべきは「入口の単一性」であって「実装の単一性」ではない**ゆえ。 |
| C-3 | 「取り得る値は次の**5つのみ**」 | 代入は **6箇所** (`unknown` を含む) / **返値と共に観測され得るは 5つ** | **字面はこのままで正しい**。`unknown` は初期値で、全ての return 路が上書きする ∴ 外からは観測され得ぬ。★但し当職は令16 前まで 3値しか測っておらなんだ★ ―― 本票で 5値すべてを観測する形を揃え申した (T-012/T-013 新設)。 |

**★字面の改訂は a2 の領分に御座る★** (契約の起草者ゆえ)。当職は **具申に留め、己では触れておらぬ**。
