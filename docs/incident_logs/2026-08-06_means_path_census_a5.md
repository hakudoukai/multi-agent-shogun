## 機械判定 (一次・キーワード+pathパターン) — 宛先付き個別下命193件が対象

**判じ方 (何を「指しておる」と見たか)**=以下いずれかを含む便を「外部の物を指す」と一次判定した:
- means語: `helper|端点|endpoint|正本|API|URL|url|http|hook|script|worktree|repo|patch|branch`
- path/hashパターン: 拡張子付きpath (.sh/.py/.md/.yaml/.json/.patch/.log等) / 既知dir配下path
  (scripts/・docs/・queue/等) / 一般的な絶対path (2階層以上) / 16〜64桁16進数 (sha256等のhash)

```
193件中 —— 外部の物を指す(一次判定) = 104 / 指さぬ = 89
104件のうち —— path/hash明記あり = 82 / 明記なし = 22
```

### 事例 — 真陽性1件の詳細 (Cycle2・patch)

`msg_20260806_083250_2d2c8a98` (shogun-second→karo-second、08:32:50、「a4の冷を解き、Cycle2を発注されたし」):
patchの**sha256とbyte数**は明記されていたが、**patchファイル自体の実体path**は明記されていなかった。
karo-second は「find -size 39313c」で実体を突き止め (`/home/hakudokai/hermes-departments/honbucho/reports/
reserveimage-cycle2-gate2-4-handoff-20260806.patch`)、その結果を含めた続便 (`msg_20260806_083708_f49315eb`、
家老second→足軽4号) で初めてpathを添えて足軽4号へ渡した。

**★この事例が示す機械判定の本質的な限界★**=`msg_20260806_083250`はworktree pathやsha256など**別の
path/hash**を含んでいたため、当職の一次regexは誤って「path明記あり」に分類していた
(先の機械判定104件中「path/hash明記あり82件」の内数として誤って数えられていた)。
∴ **「何らかのpathがある」と「必要な当のpathがある」は別物**であり、単純な正規表現一致では
後者を判定できない。この限界は**82件側にも同種の見落としが潜んでいる可能性**を意味し、
当職は82件全件の手検証を本工区の時間内には実施していない (下記「母集団漏れの自己申告」参照)。
