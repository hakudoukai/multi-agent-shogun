### 問い2⒜=`_dead_letter_second.yaml` parse失敗の因

**根治源を特定した** (`shim/hakudokai/hakudokai_secondpc_receiver_poll.py:232-254`
`append_dead_letter()`関数):

```python
existing = path.read_text(encoding="utf-8") if path.exists() else "messages:\n"
...
path.write_text(existing + entry, encoding="utf-8")
```

このスクリプトは★fileが存在せぬ時のみ★ `"messages:\n"` (値なし・以後block sequenceを続けられる形)
で初期化する設計だが、★file実測は `"messages: []\n"` (空flow-sequence・値が既に確定した形) で
始まっている★。この不一致がある状態で本関数が動くと、`"messages: []\n"` の直後に
インデント付きblock sequence項目が生テキストで追記され続け、★YAMLとして不正な構造 (flow-sequenceの
直後にblock-sequenceが続く) が積み重なる★。本関数はYAMLパーサを経由せぬ生テキスト追記であり、
既存内容の構造検証を一切行わない。

∴ ★因=① fileの初期状態が本関数の前提 (`"messages:\n"`) と食い違っていた事 (起源となった書込は
本関数以外・当職は特定していない) ② 本関数がpath.read_text+文字列結合という非構造的な追記方式を
採っており、既存内容の妥当性を検証しない事★の二つ。

**件数**: `- id: dead_` 行を数えて★総220件★。id内に埋め込まれたUnix epochから
本日 (2026-08-06) 分を推定=★69件★。★最新エントリの測時=2026-08-06T10:43:58+09:00★
(当職の本工区測時=10:45:11の直前・現に生きている書込である事を確認)。
