## 変異検査の走らせ方 (W-02 の検知法・再利用可)

★production file は一字も触れぬ★ ―― 複製へ欠陥を入れ、test 側の `WATCHER_SCRIPT_OVERRIDE` で複製を指す。

```bash
# ① 複製へ既知の欠陥を入れる (scratchpad 等 repo 外へ)
#    M1 掃除が capture 全体 grep (根治前の素朴実装) / M2 完全一致→部分一致
#    M3 composer 行の選びが 最下段→最上段      / M4 正規化から末尾空白除去が落ちる
#    M5 着弾確認から composer 行の除外が落ちる  / M6 idle 掃除の門を1箇所外す
# ② override して走らせる ―― ★口の名は file ごとに違う★ (下記の罠を見よ)
WATCHER_SCRIPT_OVERRIDE=/path/to/mutant_M1.sh bats tests/unit/test_codex_residue_negative.bats
PRESEND_GATE_WATCHER=/path/to/mutant_M1.sh    bats tests/test_codex_presend_gate.bats
# ③ ★落ちた形★ を行で記す (件数で書かず)。落ちねば其の test は本体に噛んで居らぬ
# ④ 実 script の sha256 が前後で不変である事を必ず示す
```

### ★★手順そのものに潜む罠 ―― 口の名を誤ると「不発」が「生存」に化ける★★

**当職が本日実地で踏み申した。**`grep WATCHER_SCRIPT_OVERRIDE` を a2 の file に当てて ★空★ が返ったゆえ
「口が無い」と判じ、其のまま `WATCHER_SCRIPT_OVERRIDE=… bats a2の file` を走らせた。
結果は `0/13`。之を ★「a2 の形は此の変異を捕らぬ」★ と読みかけ申した。

**実は口は在った。名が `PRESEND_GATE_WATCHER` だっただけに御座る。**
∴ 其の走行は ★mutant に一度も当たらず・本体に当たって居た★。**`0` は「生き残った」に非ず「走っておらぬ」。**

| 見た目 | 二つの正体 | 見分け方 |
|---|---|---|
| `落ちた形 0/N` | ㈠ 変異が母集団に噛まぬ (真の生存) | ㈡ そもそも mutant に当たっておらぬ (不発) |

> ### ★変異検査には ★陰性対照★ が要る ―― 「必ず赤に成る筈の mutant」を一つ先に流し、口が生きて居る事を証してから 0 を語れ★

- 具体には: 母集団が確実に捕える mutant (当職の file なら M1、a2 の file なら M3/M4) を先に流し、★赤が出る事★ を見る。赤が出ぬなら其れは ★口が効いておらぬ★。
- `grep` で口を探す時は ★変数名を決め打ちせぬ★。`grep -nE '\$\{[A-Z_]+:-.*(WATCHER|watcher)' <file>` の如く ★形で索く★。
- 之は W-03 (陽性対照) の ★裏返し★ に御座る。W-03 は「緑が空振りでない証」、本項は「★赤が出ぬ事★ が空振りでない証」。
