## 0. 直すべき物は何か(㋑㋐ の実測から)

## 1. 甲 ―― 照合器(karo_mac_manifest_verify.py)が disk 側も歩く

**形**: 照合器に歩き根の引数を足し、walk(歩き根) − 臺帳 = 員外 を第五の数として刷り、rc に入れる。

**利**: 員外が ★照合器一本★ で閉じる。呼ぶ者が誰であつても同じ答が出る。

**★退けた理由(一行)★**: 照合器の既定基点は ★repo 根★ である(逐語 `base_src = "既定(器の在處から導いた repo 根 %s ―― ★cwd に依らぬ★)"`)故、歩き根を既定へ倒せば ★13.2GB の repo 全體を歩く★ か、倒さねば「歩き根 未指定＝測れぬ＝通す」で ★fail-open を新設する★ ―― どちらも疵である。

**添への理由**: 照合器は ★多数の席の既存臺帳★ を讀む共有器であり、rc を増やせば ★既存の束が一斉に赤になる★。之は委員長裁 seq321353⑴ が「旧形を拒むな」と正した其の疵と同じ形である。

## 2. 乙 ―― 門が別條(★第六條★)として員外を測る ← ★之を選ぶ★

**形**: `karo_mac_dasumae_gate.sh` に ★第六條 員外★ を新設する。

- 入口: ★歩き根★ を宣する口(例 `KM_GATE_ARUKI_NE`)と ★除外表★(㋔・後述)。
- 式: `員外 = walk(歩き根 / S_ISREG のみ) − 臺帳の path − 除外表`。
- 出目: 員外の本数と ★名を全て刷る★。0 でない時 ★落とす★。
- 0 の時も ⑴除外表の中身 ⑵歩き根と深さ ⑶rc ⑷刻 を刷る(★零の四つの札★)。
- ★條① は一指も触れぬ★ ―― 既存の束は赤にならぬ(乙 の最大の利)。

**利**:
1. 員外は ★束の性質★ であり、束を知るのは ★納め時に呼ばれる門★ だけである ―― 情報が在る處に禁を置く。
2. 條① を変へぬ故 ★既存臺帳の一斉赤★ が起きぬ。
3. 門は既に「落ちたら止まる」形を持つ(逐語 `★出す前 門が落ちた。出すな。★`)故、器の骨を増やさぬ。

**★乙の疵(隠さず書く)★**: 歩き根が宣されねば第六條は ★數へるだけの則★ に堕ちる(「規則を器が決められねば ただの數へに成る」)。∴ 第六條は ★歩き根の宣を必須★ とし、宣が無い時は ★「第六條 = 測れぬ」と名指して刷り、且つ落とす(fail-closed)★ 形でしか据ゑられぬ。之は ★既存の全呼出を一度は赤にする★ ―― 据ゑ方(段階解禁・既定 off の期間)は家老と委員長の裁が要る。

## 3. 丙 ―― 臺帳の建て手が「束の全 file を必ず載せる」事を保つ

**形**: `karo_mac_manifest_append.py` に「束の全 file を載せたか」を検める口を足し、漏れが在れば一行も書かぬ(全か無か)。

**利**: 禁は ★書き手★ に在るのが本来である(案一・裁 seq321856 の教へ)。

**★退けた理由(一行)★**: 書き手は ★己が呼ばれた刻に未だ生れて居らぬ file★(門控・送り控・MANIFEST.txt 自身)を知り得ぬ ―― 「束の全 file」が確定するのは ★納め時★ であつて ★追記時★ ではない。

**添への理由**: 書き手に束の外延を教へる為には結局「束の根」を渡さねばならず、渡した所で ★追記の途中の束★ を歩く事になる(自分が今書いて居る MANIFEST.txt を員外と数へる)。之は本弾で己が現に踏んだ疵である ―― `raw/09b_driver_innsei_ingai1.*`(陰性対照の員外が 0 に成らなんだ走り)。

## 4. ★三案の何れも「束が己の門控を含む」問題を解かぬ★

- MANIFEST.txt は ★己の行を己に書けぬ★(書けば sha が変り、書き直せば又変る ―― 不動点が無い)。
- 門控(`_gate/*.out .err .rc .cmd`)は ★門が走つた後に生れる★ ∴ 臺帳を建てた刻には存在せぬ。
- ∴ walk(束) − 臺帳 は ★構造的に 0 に成らぬ★。甲でも乙でも丙でも同じである。
  - 甲: 照合器が歩いても門控は員外に出る。
  - 乙: 門が歩いても ★己の控★ が員外に出る(己を数へる器の疵)。
  - 丙: 書き手は門控を知らぬ。
- 家老が km-88/90 で二度実測した「全歩きの門は ★原理的に★ 通らぬ」は之である。
- ∴ ★員外の條は「除外の宣」を伴つてのみ成り立つ★ ―― 其の宣を人手でなく器で支へる道が ㋔ である。
