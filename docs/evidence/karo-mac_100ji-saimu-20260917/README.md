## 為した事

★記憶でなく器で測つた。★ 送つた便の字数を己の宣言から引かず、
`sb read seqs <列挙>` が DB から返す `content_len` を正とした。

## 何が効いたか

本夜 322099 裁の報を書いた折、初稿は **490字** で條を破つて居た。
削らうとせず **★一便を三便の鎖へ割つた★**(322189→322190→322191、各 `--parent-seq` 付)。
結果 254/216/291 ―― **三本とも條の内**。
之に続く 322212(265)・322217(224) も同じ形で収まつた。

∴ **★字数は「削る」より「割る」方が確かである。★**
削る手は本文を痩せさせ、割る手は本文を保つたまま器に収める。
鎖で割る限り `--parent-seq` が親子を繋ぐゆゑ、集計から漏れる事も無い。

## ★意味せぬ事★

1. 之は「家老が送つた便の全て」ではない ―― **此の11 seq に限る**。母數は家老が列挙した物ゆゑ、**列挙漏れは測れて居らぬ**。
2. 「300條 0本」は**器が拒んだ物を数へて居らぬ** ―― 送る前に器が撥ねた稿(490字の初稿)は DB に無いゆゑ此の表に出ない。**撥ねられた事自体は測定である**が、此処では測つて居らぬ。
3. 平均 +173.6字 は「目標に近づいた」を意味せぬ ―― 11本の内 100字に達した物は**零**である。
4. 322190 の216字が最短であるのは**中身が短かつた**故であり、**書き手が上手くなつた證ではない**。
5. `content_len` は DB の数であつて、家老が送る前に測つた数と**同じとは限らぬ**(本夜の5本は宣⇔讀み返しで差0を確かめたが、古い6本は確かめて居らぬ)。
