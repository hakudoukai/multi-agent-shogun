―― ㊁ 何故 0byte なのか・何故 EOF 改行が無いのか(因を名で) ――
  ⑴ *.lock (57) = 寫しの supervisor が flock の代りに置く ★空の錠★。
     macOS に flock(1) は無い ∴ 寫しは「file を作るだけ」で排他を表す。
     ★中身が空である事が錠の意味★ ―― 一字書けば錠ではなく「何かの記録」に化ける。
  ⑵ *.stdout (57) = 子 python の ★標準出力が空だつた事★ そのもの。
     子は log を stderr 側(>>suplog)へ出す ∴ stdout は 0byte が正しい出目。
     ★改行一つ足せば「空だつた」が「空行が出た」に化ける★。
  ⑶ *.state (57) = 寫しの stub tmux が printf %s で書く ★数取り札★(例: 「3」)。
     改行を付けぬのは stub の実装 ∴ 之も出目。1 本は 0byte(一度も呼ばれず)。
     ★改行を足せば「stub が書いた字」を私が書き換へた事になる★。

―― ㊂ 依つて取る道 ―― ★第四の道 = 宣して argv から除く★
  正す(改行を足す/零を埋める) = ★出目の改竄★ ∴ 取らぬ。
  黙つて除く                 = ★静かな失敗★ ∴ 取らぬ。
  門を書き換へる             = 生器への手出し(scope_out ⑴) ∴ 取らぬ。
  ∴ ★此の紙で宣し、門の argv から 172 を落とす★。門控は落とした事が分かる形で残す。

―― ㊃ 除いても失はれぬ事(★大事★) ――
  ⑴ 172 は悉く★歩かれて居る★。「除いた」は「歩いて居らぬ」ではない。
  ⑵ 172 は悉く★臺帳 MANIFEST.txt に行が在る★ ―― sha256 も bytes も lines も載る。
     ∴ ★宣して除いた物も母數に数へる★。臺帳の母數は 172 を含んだ数である。
  ⑶ 門 條① (臺帳 ⇔ 実体の照合) は argv と無関係に★臺帳の全行★を見る。
     ∴ 172 の sha256 は條①で現に検められる ―― 検査から逃げては居らぬ。
  ⑷ 除いたのは 條②③④⑤ (argv を見る條) のみ。其の中でも鳴るのは條④ だけである。
