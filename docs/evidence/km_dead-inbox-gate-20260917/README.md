## 一、何が病であつたか

`queue/inbox/gunshi-mac.yaml` は **母數 565通・`read: true` 0通** である（專任2 實測 2026-09-17）。
一通も讀まれた痕が無い。にもかかはらず `inbox_write.sh` は **rc=0 を返して書けてしまふ**。

> **★書けてしまふ事が、届いたと誤らせる。★**

足軽の監査提出は義務である。義務の宛先が死箱である限り、
**義務を果たした者が、果たして居らぬ事に成る。** 專任2 自身が
「提出は済んだが監査は始まつて居らぬ。監査PASSは未取得である」と書いた（本人の自白）。

## 二、据ゑた物

`scripts/inbox_write.sh`（self-send guard の直後・amplification guard の直前）

- 名簿 `IW_DEAD_LIST`（既定 `gunshi-mac`）に當たれば **rc=68** で撥ね、正路を三行で出す。
- 抜け道 `IW_DEAD_ALLOW=1`（棚卸し・移送の様な、讀まれぬ事を承知の書込み用）。
- 止まり木 `IW_DEAD_TEST_ONLY=1` → `DEAD_INBOX_PASS target=<name>` を出して exit 0。

### ★止まり木が要つた理由（己の疵・一件目）★

初走の陰性対照三本は **門に一度も届いて居なかつた**。
既存 `IW_DEFERRAL_TEST_ONLY` の `exit 0` が **此の門より手前（L48）** に在り、
`gunshi-mac` 宛の陰性が rc=0 で「通つた」様に見えた ―― **零長の比較＝偽の通過**である。
∴ 門の**直後**に専用の止まり木を置き、對照が門を必ず通る形に改めた。

### ★空名簿の出目（己の疵・二件目）★

`IW_DEAD_LIST=""` を「名簿を空にする」と宣して陰性④を組んだが、rc=68 で落ちた。
`${IW_DEAD_LIST:-gunshi-mac}` の `:-` は **空を「無指定」と同じ**に扱ひ、既定へ倒れる。

> **★對照が落ちた時、器を直すか宣を直すかは「どちらが安全側か」で決める。★**
> 此處では**器を残し宣を直した** ―― 名簿が空でも死箱が守られる方が安全だからである。
> 門を開けたいなら `IW_DEAD_ALLOW=1` を使ふ。此の判断は器の註にも焼いた。

## 五、★此の紙が意味せぬ事★

1. **「third の器と同形」とは言へぬ。** third 器は他PCに在り當席は讀めて居らぬ。
   裁の文言に在る**鍵の名（`IW_DEAD_LIST`）と挙動**のみを合はせた。**rc=68 は當席が新たに宛てた値**である。
2. **565通が救はれた訳ではない。** 門は**之から**の書込みを止めるのみ。
   既に落ちた 565通の棚卸しは Mac事業部長の持ち場（裁 322249）であり、當席は手を付けて居らぬ。
3. **軍師mac が監査を始める事を意味せぬ。** 門は誤配を止めるだけで、讀手を生まぬ。
4. **足軽が自力でDB直送出来る様に成つた訳ではない。** 三席は DB の sender を持たぬ
   （本日の便 1999 件に `ashigaru-mac-*` の `sender_agent` は**皆無**・實測）。
   ∴ 門が出す正路は實際には「**家老へ回せ・家老が代送する**」であり、其の旨を器の文言に入れてある。
5. **9/9 は「門が正しい」の證ではなく「此の9形では期待通り」の證である。**
   名に空白を含む宛先、名簿に改行を含む場合は**測つて居らぬ**。
